## Causes and corrections

1. Setup hashes newline-normalized `read_text()` content during preview, then
   compares that hash to raw file bytes during apply. Existing CRLF files therefore
   trigger a false stale-proposal error. The 19 runner errors all fail during setup
   on the unchanged ignore file, before exercising the runner. Setup now records
   exact source bytes for approval guards, including the setup baseline; migration
   previews use the predicted post-migration bytes that apply will actually see.
   Text merging remains newline-normalized. Real edits after preview, including a
   change only to line endings, still invalidate approval.
2. The unchanged-adapter fixture writes a text baseline with LF but uses a native
   text write for its adapter, producing CRLF on Windows. The installer correctly
   refuses those different bytes. The fixture now writes exactly the saved baseline
   bytes. A new regression confirms that an actual line-ending edit stays unowned
   and is not overwritten; installer ownership checks are unchanged.
3. The worktree repair test compares a native backslash path against Git's
   forward-slash porcelain output. It now parses registered paths into native Path
   objects, checks the new registration and absence of the old registration, and
   retains the branch/common-directory checks. Worktree repair itself succeeded
   in both failed CI jobs.
