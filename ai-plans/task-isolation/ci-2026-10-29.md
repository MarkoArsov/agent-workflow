# Windows worktree-registration correction

The user requested diagnosis, correction and push for PR #40. This is a continuation
of the existing isolated task, not a new specification or shared-checkout change.

Failing evidence: Verify run 40936443007 at b7400787edbc25995420df291466a96d1af00948:
https://github.com/MarkoArsov/agent-workflow/actions/runs/40936443007

All six Windows batches on Python 3.11/3.14 failed task-isolation cases with
`Task worktree is not registered at its owned path`. Linux/macOS core, docs, audit
and the Windows installation smoke passed. Complete failed-job logs were retrieved;
the six batches share this cause rather than timeouts or missing credentials.

Cause: Git's NUL-delimited worktree output uses forward-slash paths on Windows,
while str(native Path) uses backslashes. The registration check compared those
representations literally even after validating branch and Git common-directory
ownership, so it rejected a legitimate registered checkout.

Fix: parse only worktree path fields and compare resolved native Path objects.
Retain the existing branch, registration and Git common-directory checks. No check
is skipped or disabled, and unrelated registered paths still fail.

Regression evidence: the equivalent-path fixture failed an assertion against the
old code, reproducing the rejection locally. It passes after the fix. A second
fixture explicitly exercises Windows slash/case semantics with PureWindowsPath,
and verifies that a different registered path remains rejected. These semantic
fixtures are not a claim of running a Windows OS locally; hosted CI verifies that.

3,968 link/asset checks, generated wrappers and the generic source/history content
audit passed (no private denylist supplied). Hosted Windows verification follows
the normal push to PR #40. No real user agent configuration is used
by tests, and no GitHub account configuration is changed for publication.
