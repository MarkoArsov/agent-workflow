# Rebrand to plovi: rename the package, CLI, skills and docs, and restyle the docs site

Source: https://github.com/MarkoArsov/agent-workflow/issues/15
Updated: 2026-10-29T10:00:06Z

## Why

The product is now called **plovi** (Macedonian for "sails"), always written in lowercase. The design system for the new brand is in `design/`. This issue does the whole rebrand in one pass so every later issue builds on the final names, paths and look.

## Outcome

- People install and run `plovi`; skills appear as `plovi-<name>`.
- Existing installs, projects and muscle memory keep working through aliases until 1.0.
- The documentation site looks like `design/screens/docs/` and uses `design/tokens.css`.
- No user data is lost or silently moved.

## How it works today

- Runtime package: `runtime/agentflow/` (imported as `agentflow`). Launcher: `bin/agentflow` (adds `runtime/` to `sys.path`, imports `agentflow.cli`).
- Package marker: `workflow-package.json` → `{"name": "agentflow", "discovery": {"prefix": "af", "aliases": {}}}`. `runtime/agentflow/adapters.py` reads the prefix (default `"af"`) to name host skill entries (`af-implement`, `af-setup`, ...). `install.py` checks the marker name in `validate_source()` (`marker.get("name") != "agentflow"`).
- Per-project folder: `.agentflow/` (`project.json`, `package-lock.json`, `overrides.lock.json`, `project-ref.json`, `local/evidence`, `local/worktrees`, `runtime/`, `bin/agentflow`). Paths are hard-coded in `runtime/agentflow/project.py`, `install.py`, `profile.py` (`defaults()`), `adapters.py`, `setup.py` and tests.
- User data: `util.user_data()` → `$XDG_DATA_HOME/agentflow`, with an existing legacy fallback to `agent-workflow` for linked checkouts.
- Environment variables: `AGENTFLOW_PACKAGE` (tests and adapters), `AGENTFLOW_REF` and `AGENTFLOW_NO_MODIFY_PATH` (installers, CI).
- Global launcher: `~/.local/bin/agentflow` (`agentflow.cmd` on Windows); `install.py` `START_COMMANDS` prints `/af-setup`.
- Claude plugin: `.claude-plugin/plugin.json` and `marketplace.json` name `agentflow`; `cli.py` calls `claude plugin update agentflow@agentflow`.
- Skills: every `skills/*/SKILL.md` has a resolver block mentioning `bin/agentflow`; skill folder names have no prefix.
- `PROJECT_WORKFLOW.md` and `CLAUDE.md` are generated between `<!-- agentflow:start -->` and `<!-- agentflow:end -->` markers by setup.
- Docs: `mkdocs.yml` (`site_name: Agent Flow`, `extra.brand: agent flow`, `asset_version: agentflow-4`), templates in `templates/site/` (a rename banner in `main.html` says "Scorebook is now Agent Flow"), CSS in `docs/assets/css/` (own tokens, IBM Plex fonts in `docs/assets/fonts/`), brand files in `docs/assets/brand/`, diagrams in `docs-data/diagrams/` (`.mmd` and generated `.html`), generated pages via `scripts/generate_docs.py` and `scripts/docs_hook.py`.
- CI: `.github/workflows/verify.yml` `windows-install` job checks `~/.agents/skills/af-setup/SKILL.md` and `agentflow.cmd`; `pages.yml` builds the site.

### Part 1: Code and package names

2. `bin/plovi` becomes the launcher. Keep `bin/agentflow` as a thin wrapper that prints one line to stderr (`agentflow is now plovi; this alias works until 1.0`) and runs `plovi` with the same arguments and exit code.
3. `workflow-package.json`: `"name": "plovi"`, `"discovery": {"prefix": "plovi", "aliases": {"af": "plovi"}}`. `install.validate_source()` accepts `plovi` and, for one release, `agentflow` (so updating from an old checkout works).

6. Launchers: installers write `plovi` (`plovi.cmd` on Windows) and keep an `agentflow` launcher alias. `START_COMMANDS` and installer output use `/plovi-setup`.

### Part 2: Project folder and user data migration

1. The per-project folder becomes `.plovi/`. In `project.py` resolution: if `.plovi/project.json` exists, use it. Otherwise, if `.agentflow/project.json` exists, migrate:

2. `.gitignore` entries written by setup use `.plovi/local/`; keep the old entry if present.
3. `util.user_data()` → `$XDG_DATA_HOME/plovi`. If it does not exist and `$XDG_DATA_HOME/agentflow` (or the older `agent-workflow`) exists, rename it once, the same way.
4. Profile defaults in `profile.py` use `.plovi/...` paths.

## Pitfalls

- `git mv` the runtime folder in its own commit before editing files, so history follows.
- Windows: `os.replace` of a directory fails if any file inside is open; close handles and give a clear retry message.
- Do not rename user content inside `.plovi/skills`, `rules`, `references` or `connectors`; only paths in `project.json`.
- Search for `"agentflow"` in JSON fixtures under `tests/fixtures/` too.
- The docs build runs `scripts/docs_hook.py`; check it for hard-coded names.
