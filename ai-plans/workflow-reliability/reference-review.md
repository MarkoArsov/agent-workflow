# Read-only reference comparison

The user-authorized reference workflow was reviewed again for stage ownership,
autonomous continuations, artifact recovery, provider failure handling, detached
execution, event streams and tracking. Private code, paths, identifiers and skill
bodies are deliberately not included in this public artifact.

| Observed reference behavior | Existing plovi gap | Planned improvement |
| --- | --- | --- |
| Mechanical fixture defects stay in the fixing workflow | File hashes freeze all test content and implementation escalates | Independent bounded fixture repair, preserved behavioral contract and renewed proof |
| Known recoverable stops receive bounded correction | Every reported spec conflict currently becomes a hard stop | Structured recovery categories with verified eligibility; true product decisions still pause |
| Stage artifact recovery avoids repeated requests | Partial support exists but runtime/source divergence caused manual intervention | Journaled safe recovery and pinned runtime with explicit adoption for unknown changes |
| Watch follows events and emits heartbeats | Earlier watch dumped full state; current compact fix still lacks live activity | Cursor-based redacted events, live summary and independent activity/heartbeat timestamps |
| Foreground launch detaches worker then observes | Users needed worktree-specific command paths | Stable host entry point and tracking descriptor tied to the same run |
| Verification belongs to implementation, not its narrative | Red subset passed while other fixtures were broken | Fixture-health checks plus complete green acceptance and independent review |

Improve beyond the reference where evidence warrants it: avoid regex-only decisions
about whether to override a stop; do not infer liveness from PID existence alone;
make reviewer advisory text distinct from actual failed checks; bound report repair
and usage; protect the selected account; keep generic capability adapters and
precise native support evidence. Review findings that demonstrate a real correctness
failure must not be ignored merely to continue to publishing.

Broad factory ambitions are staged: reliability and trust first, then reusable
observability/host integration, then throughput and scheduling after the foundations
are demonstrated. Do not equate perfection with an absence of visible stops.
